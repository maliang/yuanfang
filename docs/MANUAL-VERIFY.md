# 真机验证清单

自动化已经覆盖：类型检查、core smoke（faux provider 的对话/项目/任务/锁/审批/MCP）、Electron 静默启动 + 主界面/新建项目/设置/项目页/快速提问窗口截图。
下面这些只能在真机上由人确认（或用户明确说「真机验证」时一次性做）。

## 1. 全局快捷键

1. 启动 `npm run dev`。
2. 切到任意其他 App（浏览器、编辑器）。
3. 按当前设置中的快捷键（默认 `⌘⇧Space`）。
4. 期望：屏幕上方出现「元芳」快速提问框，输入框自动聚焦；再按同一快捷键或 `Esc` 关闭。
5. 在输入框输入一句话，按 Enter。
6. 期望：输入框消失，任务栏出现「元芳」通知；点击通知回到主窗口，右侧对话栏显示这条对话。

> 注意：开发模式下通知可能显示为 Electron；打包后才显示「元芳」和图标。

## 2. 任务栏通知与点击跳转

1. 在右侧对话栏输入一个会创建项目的请求（例如「做一个测试项目，在根目录写 hello.txt」）。
2. 等待系统回复 / 项目创建。
3. 期望：任务栏弹出简要通知；点击后主窗口前置，并跳到对应项目（或对话）。

## 3. 托盘

1. 看菜单栏右侧是否有「元芳」托盘图标（模板图标，随深浅色变化）。
2. 单击：打开主窗口。
3. 右键 / 菜单：打开元芳、快速提问、打开工作区、退出。
4. 关闭主窗口（红灯）后，托盘仍在；点击可重新打开。

## 4. 快速提问窗口

1. 使用设置中的快速提问快捷键呼出。
2. 点击窗口外任意位置：窗口应自动隐藏。
3. 输入中文（拼音输入法），确认组合输入不会误发送；Enter 发送。
4. 发送后不立刻点任何地方，等待通知。
5. 如果通知到达时快速窗口还没关，窗口内应显示元芳回复摘要和「查看完整对话」按钮。

## 5. 顶栏拖拽与交通灯

1. 拖动顶栏空白处，窗口应移动。
2. 顶栏按钮/导航可点击，不会触发拖拽。
3. 左上角红黄绿交通灯位置正常，不与「元芳」logo 重叠。

## 6. 停止 / 未读 / 验收

1. 对元芳发一个需要多步工具的任务。
2. 运行中右侧底部出现「停止」；点击后当前 run 中断，输入框仍可继续发消息。
3. 折叠对话栏后收到回复，折叠条上出现未读徽标；展开后归零。
4. 让项目负责人完成一个任务：任务先进入「待验收」，不会直接变 done。
5. 在任务详情点「通过验收」→ done；点「退回重做」并填写原因 → todo，可再次派发。

## 7. 任务时间线 / diff

1. 派发一个会 `edit` 或 `write` 文件的任务。
2. 打开任务详情：工具时间线应出现 edit/write/bash 记录；edit 的 diff 应显示在时间线里。
3. 任务结束后事件仍保留；重试任务会追加新记录。

## 8. 审批

1. 对元芳说：「帮我安装一个 npm 包 left-pad，然后创建一个测试项目用它」。
2. 期望：元芳先调用 `request_approval`，任务栏/审批面板出现待审批项，命令预览正确。
3. 先点「拒绝」，期望请求方收到拒绝消息，不再执行安装。
4. 再来一次，点「批准」，期望请求方收到批准消息，然后才执行 `npm install`。
5. 审批面板「历史」里能看到批准/拒绝记录和备注。

## 9. MCP / 插件 / 技能管理

1. 对元芳说：「接入 MCP：命令 node，参数 [\"<某个 MCP server 路径>\"]」。
2. 期望：生成 MCP 审批，详情里能看到命令。
3. 批准后，期望日志出现「MCP ... 已连接，N 个工具」，设置页插件/MCP 状态正常，Agent 工具列表出现 `mcp_...`。
4. 拒绝时不应启动子进程。

## 10. 同文件并发

1. 创建一个项目，让项目负责人拆两个任务，两个任务都要改同一个文件（在任务 `files` 里写同一个路径）。
2. 同时派发两个任务。
3. 期望：任务卡片都显示 running；UI 顶栏出现文件锁指示；两个角色 Agent 的 `edit/write` 不会交错，后一个等待前一个释放。
4. 观察两个任务的对话：不应出现同一段 `oldText` 被两边同时匹配导致的乱改。

## 11. 项目卡片与统计

1. 至少完成一个任务。
2. 期望卡片显示：项目名、简介、总用时、tokens、缓存命中、创建时间、最后更新时间、完成/进行中数量。
3. 点击卡片进入项目页：任务板、架构、记忆、项目对话四个 tab 正常。
4. 点任务「查看」：右侧出现任务详情和角色对话。

## 12. 厂商凭据

1. 打开设置 → 厂商与凭据。
2. 左侧应看到厂商列表；右侧显示来源（远方 / 来自 Pi（如果本机有 Pi）/ 环境变量）。
3. 选一个未配置厂商，粘贴一个测试 Key，点「保存并拉取模型」。
4. 期望：右侧模型数增加 / 出现模型；点「系统」后上方系统模型被填入，保存设置后生效。
5. 重新打开设置：该厂商显示「已配置 · stored credential」和「远方保存」；点删除只删除远方凭据。
6. 如果显示「来自 Pi」，它不应出现删除按钮；点「从 Pi 导入凭据」可以复制到远方。

## 13. OAuth-only 厂商

1. 设置 → 厂商与凭据，选一个只有 OAuth 的厂商（例如 Anthropic OAuth / GitHub Copilot）。
2. 右侧应出现 OAuth 区块和「登录」按钮，而不是只显示文字提示。
3. 点击登录：主进程应在浏览器打开授权页；如果 provider 需要输入 code，UI 会出现输入框。
4. 完成后厂商变为已配置，模型列表刷新；来源显示「远方保存」。
5. 取消登录应中止并提示。

> 这一段需要真实 OAuth 账号验证，自动化只验证了 UI 和 IPC 通路。

## 14. 角色 / worktree / workflow / 预算 / 插件审批

1. 设置 → 角色：修改一个内置角色的 instructions，并给它指定不同模型；派发该角色任务后任务详情 model 应使用该模型。
2. 设置开启「每个任务使用独立 git worktree」，项目为干净的 git 仓库。
3. 派发任务后，任务详情显示「独立工作区」；项目主目录不应出现角色改动，验收通过后自动合并。
4. 任务详情可看到阶段；项目页显示 workflow；在非最后阶段点「通过验收」应被拒绝，`advance_task` 推进到最后阶段后才能通过。
5. 设置每日 token 预算为 1，跑一轮后新任务应被拒绝并给出警告。
6. `plugin_write` 后应出现「插件」审批；批准后才加载，拒绝不加载。

## 15. 通知中心

1. 触发一次审批/项目完成/任务待验收。
2. 顶栏「通知」出现未读徽标；打开后列表有记录。
3. 点一条系统回复通知：应展开右侧对话并滚动到对应消息。
4. 点一条项目通知：应打开对应项目。
5. 「全部已读」后徽标归零。

## 16. 设置 / 外观 / 快捷键 / 备份 / 通知级别

1. 设置页左侧有「外观 / 身份 / 模型 / 凭据 / 运行 / 工作区 / 扩展」栏目，右侧只显示当前栏目内容。
2. 在「外观」切换深色 / 浅色 / 跟随系统，并选择 90%–120% 界面字号；保存后立即应用且重启保留。
3. 在「运行 → 快速提问」修改快捷键（例如 `CommandOrControl+Shift+K`），保存后立即生效；换到其他 App 按新快捷键应呼出快速提问窗口。输入一个被系统占用的组合时应提示无法注册。
4. 设置页搜索模型，确认下拉框按 query 过滤。
5. 修改「系统 Agent 名称」并保存：顶栏、对话栏、快速提问、托盘提示、通知标题都应更新。
6. 修改「每项目最大并发任务」为 1；同时派发两个任务，第二个应被拒绝并给出提示。
7. 通知级别切到「只弹重要」：普通回复不再弹，审批/失败仍弹。
8. `npm run backup` 后检查 `~/.yuanfang/backups/<时间>` 有 sqlite/config/persona/mcp/roles。

## 16.5 新建项目 / 已有目录理解

1. 点顶栏「+ 新项目」，选择「选择文件夹…」，指定一个已有代码目录。
2. 期望：项目名自动带出目录名；出现「理解中」，随后项目简介由 AI 填写，显示读取到的文件数。
3. 如果当前模型不可用，期望仍显示本地目录摘要和警告，允许手动修改后创建。
4. 点「创建并启动」后，期望项目正式建立文件索引，项目页架构/记忆中有该目录内容。
5. 项目位置输入 `/` 或用户主目录时应被拒绝。
6. 只有顶栏保留一个新建项目入口；有项目时首页不再显示大幅欢迎区，项目列表直接出现在上方。

## 17. 更新

1. 打包 `.app`，设置更新源为一个 generic provider 的 `latest-mac.yml`。
2. 发布一个更高版本 + zip/dmg。
3. 启动旧版：应弹出「发现新版本」；点「现在更新」后下载，下载完成提示重启安装。
4. 点「现在更新」前不应自动下载。

## 18. 打包后的通知名称/图标（unsigned .app 已验证）

当前没有安装包。打包后需要确认：

- 通知标题是「元芳」而不是 Electron；
- 通知/托盘/Dock 使用 `apps/desktop/resources/icon.png` 和 `trayTemplate.png`；
- 代码签名后通知点击能正常唤起 app。

## 自动化静默验证（可重复）

```bash
cd apps/desktop
YUANFANG_E2E=1 YUANFANG_E2E_CAPTURE=1 YUANFANG_HOME=/tmp/yuanfang-e2e-home \
  ../../node_modules/.bin/electron .
```

产物：

- `/tmp/yuanfang-e2e/home.png`
- `/tmp/yuanfang-e2e/new-project.png`
- `/tmp/yuanfang-e2e/settings.png`
- `/tmp/yuanfang-e2e/quick.png`
- 如果工作区有项目：`/tmp/yuanfang-e2e/project.png`
- 终端里的 `E2E_RESULT {...}` JSON：DOM 断言。

E2E 模式默认 `opacity=0`、`showInactive`、`dock.hide()`，不会出现在屏幕上。需要肉眼可见时显式设 `YUANFANG_E2E_VISIBLE=1`（仅在你同意时）。
